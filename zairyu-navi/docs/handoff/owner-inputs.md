# 只有负责人能提供的东西

上线前要你给出的信息和要你做的决定。每一项写了：填到哪里（环境变量、文件、页面）、不填会怎样、建议的默认做法。环境变量的规则以 `README.md`“运行”“服务商入驻”两节为准；写错了服务器不启动，并说明是哪一项。

**怎么交**：
- 公司信息、金额、文字类的：直接发给开发，开发填进页面。
- 密钥类的（`ANTHROPIC_API_KEY`、`MAIL_HTTP_KEY`、`SMTP_PASS`、`ADMIN_TOKENS`）：**不要发在聊天、邮件、issue 里，也不要写进代码仓库**。你自己在服务器（或云服务商的“环境变量 / Secret”设置）里填。
- 填好以后让开发跑一次 `npm test` 和 `npm run e2e`，再在正式环境用 `npm start` 启动看有没有报缺项。

- **填到哪里**：
  - `web/terms.html` 第1条“在留导航由【运营公司名称】提供”
  - `web/privacy.html` 第1条“【运营公司名称】……地址【 】”
  - `web/provider-terms.html` 第1条“运营者【公司名】”
  - 邮件末尾：现在所有邮件只写“—— 在留导航／这是系统自动发出的邮件，请不要直接回复。”（`src/mailer.js` 的 `SIGN`、`PSIGN`），没有运营者名称和地址。要不要加，等律师回答 `lawyer.md` 的 Q4；要加的话是开发改代码。
- **注意**：改了这三份页面的文字，按 README“条款版本”的规则要改版本号；现在还没有真实用户，上线前当天改可以不改。

## 2. 联系窗口邮箱

- **要给**：
  - 用户的个人信息咨询窗口（开示、订正、删除等请求）→ `web/privacy.html` 第1条“个人信息咨询窗口【邮箱】”
  - 服务商的联系窗口（资料变更等）→ `web/provider-terms.html` 第2条“须及时联系运营者（【联系窗口】）”
- **建议**：两个不同的地址，都在第 3 项的域名下（例：`privacy@你的域名`、`partners@你的域名`），要有人定期看。不要用发信用的 `no-reply` 地址——所有自动邮件都写着“请不要直接回复”。
- **注意**：用户的账号是匿名的。按已定的规则，原来的邮箱收不到信时客服**不**替人更换或解除邮箱（`docs/TODO.md` 第 2 条）；处理窗口来信的人要知道这一条，律师对它的意见见 `lawyer.md` Q15。

## 3. 域名

- **要给**：正式的网址。
- **填到哪里**：
  - `APP_URL`：例 `https://navi.你的域名`（`http://` 或 `https://` 开头，不带参数）。提醒邮件里的“打开在留导航”和退订链接、服务商邮件里的工作台链接都用它。`MAIL_SENDER` 是 `http` 或 `smtp` 时必填。
  - `MAIL_FROM`：例 `在留导航 <no-reply@你的域名>`。
  - 发信域名的 SPF、DKIM（在域名的 DNS 里按邮件服务商的说明设；`docs/TODO.md` 第 2 条）。
- **建议**：自己持有的 .jp 域名；App 用子域名（`navi.`），发信用同一个域名。

## 4. 邮件发送服务商

- **要定**：用哪一家、在哪个国家处理数据。
- **填到哪里**：
  - 服务器环境变量（`README.md`“运行”的表）：
    - 用 HTTP 接口（建议先用这个）：`MAIL_SENDER=http`、`MAIL_FROM`、`MAIL_HTTP_URL`、`MAIL_HTTP_KEY`。程序发的请求是 `POST MAIL_HTTP_URL`，头 `Authorization: Bearer MAIL_HTTP_KEY`，JSON `{ from, to, subject, text, headers }`，返回 2xx 算成功。**选定的服务商接口不是这个格式时，要开发在 `src/mailer.js` 加一种 `MAIL_HTTP_PRESET`**（现在只有 `generic`），选之前先让开发看一眼它的接口文档。
    - 用 SMTP：`MAIL_SENDER=smtp`、`SMTP_HOST`、`SMTP_PORT`（默认 465）、`SMTP_USER`、`SMTP_PASS`、`MAIL_FROM`。只支持 465 端口的 TLS 直连，不支持 STARTTLS（587）。
    - 同时要配好 `APP_URL`、`BILLING_PLANS`、`BILLING_BANK_TEXT`，否则不启动。
  - `web/privacy.html` 第5条“通过【邮件发送服务商名称和所在地】发出”；服务商在国外时还要补“【服务商在国外时：写明所在国、该国的个人信息保护制度和对方采取的保护措施。】”。
- **选服务商时要满足**：HTTP 接口（上面的格式或开发能适配）或 465 端口 SMTP；能带自定义邮件头（提醒邮件要带 `List-Unsubscribe`、`List-Unsubscribe-Post`）；支持 SPF／DKIM；最好能推送退信通知（退信停发还没接上，`user_emails.bounced_at`、`provider_contacts.bounced_at` 只建了列）。
- **建议**：数据在日本国内处理的服务商。提醒邮件里有用户在办的手续名称（隐私政策第5条已写明），选国外的服务商要按个人信息保护法第28条补告知，可能还要另外取得同意（律师 `lawyer.md` Q2）。
- **注意**：没选定之前保持默认 `MAIL_SENDER=outbox`（邮件只留在库里，`GET /api/admin/outbox` 能看到），什么都发不出去：用户收不到验证码、服务商收不到批准邮件和账单。

## 5. 云服务商和地区

- **要定**：用哪一家、哪个地区。
- **填到哪里**：
  - `web/privacy.html` 第5条“数据存放在【云服务商名称和所在地区】”。
  - `web/privacy.html` 第8条“【备份的保存期限和清除方法】”。

## 6. 展示费金额

- **要给**：士业（行政书士、税理士、社会保险劳务士、司法书士）和其他（学校、不动产、电话卡、驾校、陪同翻译）两档的月额，日元、**含税**。
- **填到哪里**：
  - 环境变量 `BILLING_PLANS`，JSON，例：`{"regulated":11000,"other":5500}`。可以再按类别单独写（例 `"estate":8800`），值是 0 到 1000000 的整数；`regulated` 和 `other` 两档必须有。
  - `web/provider-terms.html` 第3条“展示费为固定金额【金额】日元／【期间】（含税）”：金额照 `BILLING_PLANS` 写，期间写“月（日本时间的自然月）”（系统只支持按自然月）。
- **注意**：代码里的 11000／5500 只是占位，**金额仍待你提供**（`docs/TODO.md` 第 7 条）。改价目表后新开的账单记新版本号，已开的不变。不给个别服务商打折，没有单独调价的接口（已定的规则）。

## 7. 振込先说明

- **填到哪里**：环境变量 `BILLING_BANK_TEXT`（一段文字，原样写进账单邮件和服务商工作台）。程序会自动在后面加上“转账时请在汇款人名称的前面写上参考编号 ……，我们按它确认入账。手续费由付款方负担。”，这句不用你写。

## 8. 适格请求书发行事业者的登记号

- **要给**：登记号（`T` 加 13 位数字）。你 2026-11-27 确认由你自己去办登记。
- **填到哪里**：环境变量 `BILLING_INVOICE_REG_NO`；`web/provider-terms.html` 第3条“运营者开具适格请求书（登记号【登记号】）”。填了以后账单和邮件里写登记号、10% 税率和税额。
- **时间上要注意**：已定的方针是“登记前不开始收费”，但**代码不会替你拦**：不填登记号也会照常开账单（只是不写登记号和税额）。按现在的设置，服务商在批准日 D 之后免费到 D+30，第一张要付钱的账单在开始收费那天（D+31）之前 14 天（`BILLING_ISSUE_DAYS`）、也就是大约 D+17 开出（服务商领取了令牌才开）。所以：**拿到登记号之前，不要批准任何服务商的入驻申请**，或者最晚在预计拿到登记号的 17 天之前才开始批准。

## 9. `ANTHROPIC_API_KEY`（助手用）

不配的话助手接口返回 503，其他功能照常。步骤：

1. 用公司的账户在 Anthropic 的开发者控制台（Console）开通 API，设好付款方式。
2. 在控制台设每月的花费上限（先设小一点，跑完题集看实际费用再调）。
3. 新建一个 API key，只给这个服务用。key 只显示一次，存进密码管理器。
4. 在服务器的环境变量里设 `ANTHROPIC_API_KEY`。不要写进代码仓库、聊天或邮件。
5. 其他相关变量用默认值即可：`MODEL`（默认 `claude-sonnet-5-5`）、`EFFORT`（默认 `medium`）、`MAX_TOKENS`（默认 8000）。写错了不启动。
6. 上线前用真实模型跑题集（`README.md`“用真实模型跑题集”，`docs/TODO.md` 第 3 条），在本机或服务器上：
   - 先试两题：`ONLY=A1,C1 npm run eval`
   - 再跑全部 68 题：`npm run eval`；分别用 `EFFORT=low` 和 `EFFORT=medium` 各跑一次，比较通过率、费用和耗时再定默认值。
   - 费用：README 粗估 Sonnet 5.5 跑一轮全部题 10 美元上下，以结果文件里的 `estimatedCostUsd` 为准。遇到 429 把 `CONCURRENCY` 调小；中途断了用 `RESUME=结果文件` 接着跑。
   - **程序只比对分类标记，内容要你（或你指定的人）逐条复核**：打开结果文件，对每一题按 `criteria` 读 `answer`，把 `criteriaOk` 从 `null` 改成 `true` 或 `false`。重点看 35 道必须通过的题、所有拒答的题、金额期限法条有没有自己编、有没有说“已经发送”或推荐某一家。上线条件：35 道必须通过的题分类全对、判定要点全部复核为合格。
7. 隐私政策第5条已经写了对话会发给 Anthropic（美国）；律师对告知和同意的意见见 `lawyer.md` Q1，改不改由律师的回答定。

## 10. `ADMIN_TOKENS`（管理后台）

- **写法**：`名字:令牌,名字:令牌`。名字是 1 至 32 个小写字母、数字、横线、下划线（例 `owner`、`reviewer1`）；令牌至少 24 个字符，不能有空白和逗号。名字会记进留痕和审核记录（批准服务商时的“核对人”）。
- **生成令牌**：在自己的电脑上运行 `openssl rand -hex 32`（得到 64 个字符），每个人一个，不要共用。
- **建议**：每个会审核服务商的人一个名字；只用 `ADMIN_TOKENS`，不再配旧的 `ADMIN_TOKEN`（它的名字一律记成 `admin`，分不出是谁）。令牌存进各自的密码管理器；有人不再负责时，从变量里删掉他那一段并重启。
- **用在哪**：`web/admin.html`（首页不链接，打开后输入令牌；令牌只留在页面内存里）。审核士业和不动产时必须写核对方式（所属会检索、证书、电话确认）和核对日期。
